# 検証範囲と残る確認

ここでは過去の実機観測と、現在のソースから再実行できる自動検査を分けて示します。過去の生の測定ログやVRMモデルは同梱しません。数値は一台のWindows PCの少数回測定であり、一般的な性能保証ではありません。

## 現在のソースから再実行できること

```powershell
npm ci
npm run check
npm audit
```

`npm run check` は型検査、モデル不要の単体テスト、Windows向けBuildを順番に行います。[CI設定](../.github/workflows/windows-check.yml)も同じ基礎検査を行い、Electronの実画面・入力、実VRM、実OpenAI、実VOICEVOXは実行しません。CIの成功は、人が日常使用して使いやすいという評価ではありません。[自動検査の範囲](ci.md)

## 過去に観測した範囲

| 条件 | 過去の観測 | 読み方 |
| --- | --- | --- |
| 2026-09-13、動く表示・静止・静止追従・非表示を各5分 | 動く表示はCPU平均約1.043%（PC全体比）、約24.45fps。Working Set平均は区間ごとに約502〜513 MiB。CPU・メモリ604点、GPU596点が有効。終了後に記録対象の残存は0 | 同一PC・同一サンプルVRM・当時のBuild。数時間の動く表示や別PCは未検証 |
| 2026-09-13、静止表示・画質切替・会話20回・非表示を含む2時間 | CPU平均約0.032〜0.047%（PC全体比）、Working Set平均約476〜519 MiB。GPU3,592点が有効、正常終了・残存0 | 別Buildの静止中心の測定。外部AI・実音声と同時に2時間使った結果ではない |

Working Setの合計は共有メモリを重複して数え得ます。別起動のVOICEVOXは含みません。測定時のサンプルVRMは同梱していないため、数値の厳密な再現には同じモデルと環境が必要です。

## モデル選択が後から再表示する問題

過去の検査では、モデル選択の結果が遅れて届く間に「隠す」を押すと、古い結果によって表示が復活する不具合を再現しました。選択ごとの番号を保持し、隠す・休止・再選択・終了などで古い番号を無効化するよう修正しました。修正後、遅延結果・保存待ち・再選択を含む自動検査10項目と模擬休止9項目は成功しました。

これはアプリ内部で応答を遅らせた検査で、実ファイル選択窓やOSのスリープを全条件で確認したことではありません。現行実装は[main](../src/main.ts)と[モデル状態](../src/model-policy.mjs)、関連テストを参照してください。

## 操作と画面で確認を残すこと

以前のWindows検査では、クリック透過の表示、ポインター移動、窓への追従、非表示・復帰、会話窓の開閉を対象のPCで確認しました。今回のソース公開に際して、それらを新たに実機で一通り再実行したとは扱いません。実VRMを用いた画面、実マウスと日本語IME、別PC・複数画面、実スリープ／ロック、長時間の日常使用、実AIと音声の自然さは[本人の確認手順](user-check.md)に従って別途評価します。

直接ドラッグでは、作業中の他アプリの入力先が外れる問題が残ります。通常操作はクリック透過を維持するMキー配置とし、直接ドラッグの改善完了とは主張しません。メモリ約0.5 GiBは軽量性の強みではなく、Electronを選んだ代償として扱います。
