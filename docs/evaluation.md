## 負荷計測

以下の測定値はこのPC上の短時間の開発ビルド検証であり、長時間の安定性やほかのPCの軽さを保証しない。ElectronをPlaywrightで起動して測定し、計測操作自体の影響も含む。他アプリを停止して専有した環境ではない。

- Windows 11 Home 10.0.26200、16論理CPU、約15.8GiB RAM。
- Intel UHD Graphics / NVIDIA GeForce GTX 1650。GPU計測は当該アプリのPIDに帰属するエンジンのみ。
- 主画面1920×1080、作業領域1920×1032、倍率100%。別画面も125%で接続されていた。動作対象は主画面だけ。
- AvatarSample_A、18,495,760 bytes、46,984 triangles、20 draw calls。VRM 1.0。
- 表示300×440、DPR1、30fps上限、影なし。実測FPSは上限より低く、30fps固定達成を主張しない。
- CPUの最終記録は対象プロセスの累積CPU秒を、起動後経過秒と16論理CPUで割ったPC全体比。表示・非表示・起動・操作窓表示を含む混合区間で、待機中だけの値ではない。メモリは対象プロセスのWorking Setの合計（共有ページの重複を含み得る）とPrivate Bytesの合計。
- GPUはWindows `GPU Engine/Utilization Percentage` を2秒間隔で取得。同一物理エンジンについて対象PIDを合算し、最大値を代表値にする。PC全体のGPU使用率とは異なる。

| 測定 | 結果 | 限界 |
| --- | --- | --- |
| 表示中GPU | 平均2.30%、最大3.62%（60サンプル、約2分） | 主画面300×440で当該アプリに帰属する最も忙しいGPUエンジン |
| 非表示中GPU | 平均・最大0.00%（30有効サンプル、約1分） | 途中でWindowsカウンターの無効値が発生。無効値を0にせず除外して再測定 |
| CPU | 起動後466秒の平均0.41%（PC全体比、16論理CPU） | 表示・非表示を含む混合区間。純粋な待機負荷ではない |
| メモリ | Working Set合計582.2MiB、Private Bytes合計498.5MiB | 停止合図後、Avatar非表示・操作窓表示、5プロセスの一時点。ピークや安定値ではない |
| FPS | 表示区間末尾25.9fps、途中26.4fps | 30fpsは上限であり実測は未到達 |
| 非表示の描画 | 約221秒、3,738フレームから増加なし | 非表示はVRMを解放する操作ではないので、メモリは保持 |

## 残る確認

- **タイトルバーの実ドラッグは未検証。** Computer Useのドラッグでは位置が変わらなかった。原因は未特定。矢印ボタンと移動イベントの追従は別途確認したが、ドラッグ成功へ読み替えない。
- トレイのメニューは実装済み。実マウスでの通知領域アイコン選択とメニュー全項目の通し操作は未検証。終了用ショートカットは実操作した。
- キャラクター自身の不透明画素上の実クリック、ダブルクリック、ショートカット競合、壊れたモデル全般、スリープ復帰、長時間、バッテリー、高負荷時、別GPU・別VRM、インストーラー配布は未検証。
- 実機に画面が2枚あるため、物理的に1枚だけ接続した環境を検証したとは言わない。複数画面対応も完成していない。
- 現段階ではキャラクター全体がクリック透過。直接キャラクターをつかむ体験や呼びかけ・会話はまだない。
- 新アプリはlocal Gitのみ。新GitHubの公開範囲・アプリ全体のソースライセンスは未決定。

## 判断と次の区切り
