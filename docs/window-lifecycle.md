# 窓の開閉と実会話を確かめる

通常の起動・終了手順は[README](../README.md)。以下は開発環境で使う検査で、通常のしずくを終了してから1本ずつ実行する。検査中は自分のアプリの窓が開き、操作窓と会話窓の間で入力先を切り替える。他のアプリの入力や内容を取得・操作せず、OSのスリープ・ロックも行わない。

## 自動操作の接続を使わない開閉検査

```powershell
npm run check
npm run test:window-lifecycle
```

ローカルVRMを選択済みのWindows環境を使う。PlaywrightやCDP（ブラウザーの自動操作用接続）を起動せず、実ElectronのAPIと自分のrendererのDOM操作で検査する。OSに実キーや実マウスを送る検査ではない。

呼びかけ時の入力先維持、送信後の入力復帰、設定のEsc、返答待ち中の操作窓と会話窓の終了重複20回、古い返答の破棄、新しい会話の初期状態、模擬休止と復帰を確認する。実BrowserWindowとWebContentsの破棄を毎回待ち、アバターだけが残ることを調べる。終了が実際に重なったことも記録する。

独立した検査設定を使い、モデルは読み取り専用。外部AIキーを起動環境から除き、mainのネットワークを拒否する。既存のrendererの通信制限は維持する。最大3分で中断し、Ctrl+Cでも中断できる。記録はGit対象外の`work/window-lifecycle-*/result.json`と`events.jsonl`へ残す。強制停止が必要だった実行は失敗扱いにする。

終了確認では、ElectronのPIDと開始時刻をWindows側の値と照合する。管理情報に終了済みの項目が残る場合があるため、カーネル上での生存と開始時刻を確かめ、管理情報の親PIDは開始時刻が一致する場合だけ使う。開始時刻を記録できない起動用・補助プロセスでは、記録した実行名と親PIDを照合する。Windowsが同じPIDを別プロセスへ再利用しても、しずくの残存プロセスとは扱わない。照合できなければ未確認として失敗にする。この確認はプロセスを終了させる操作を行わない。

## 実AIから音声まで1回通す

利用者のAPIキーと、別に起動済みのVOICEVOXが必要。次の準備確認はAI送信・音声合成を禁止したまま、通常のアプリで返答先と音声の選択まで進める。

```powershell
node scripts/live-conversation.mjs --prepare-only
```

実際に通す場合だけ、次を明示する。**OpenAIへの短い確認文を1回送り、通常のAPI料金が発生する。返答はVOICEVOXで読み上げられる。** 自動再試行はしない。

```powershell
node scripts/live-conversation.mjs --live-once
```

通常モードのBuildをGit対象外の一時フォルダへコピーし、独立した設定で起動する。VRM・キーはコピーしない。キーは起動環境からmainへ渡し、通常の製品処理で子プロセス生成前に削除されることを確認する。`SHIZUKU_TEST`を使わず、会話と音声の提供元も差し替えない。mainの通信には、公式Responses APIを1回、固定のローカル音声クエリーと合成を各1回だけ許可する検査用の制限を重ねる。VOICEVOXの起動・停止は行わない。

確認するのは、実返答の表示、実WebAudioの開始、口形の正の値、音声終了後のミュート・口形0・AudioContext解放、会話を閉じて呼び直したときの履歴なし・定型返答・音声オフ。会話窓を開く入口には、自分の実トレイメニューのコールバックを使う。実クリック・実IME・聴取品質の評価とは区別する。

既存設定・元モデル・元Buildが変わらないことと、記録対象プロセスの終了を確認する。音声データは保存せず、確認文への返答・数値・自分のアプリの画像だけを`work/live-conversation-*/`へ残す。キー・モデル・画像・ログをGitへ追加しない。通常の単体テストとCIは、この有料検査を実行しない。

実施結果と制限は[検証記録](evaluation.md)を参照する。接続なしの開閉成功だけで、以前のCDP条件での異常終了の根因が分かったとは扱わない。
