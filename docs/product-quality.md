# 普段そばに置きたいしずくへ

2026-09-10、利用者は就活向けの見せ方より、プロダクト自体を良いものとして完成させることを優先した。しずくの基準は、静かにいて、呼べば応え、作業を邪魔せず、また明日も起動したくなること。

## 最初の完成範囲

Windows・主画面1枚・手動起動から、次の一連の使い方を仕上げる。複数画面、万能なPC操作、常時マイク・画面監視は含めない。

| 場面 | 仕上がりの基準 | 現在の不足 |
| --- | --- | --- |
| 起動して置く | 必要な準備が分かり、選んだ場所・姿・大きさで静かに現れる | 新しい環境の導入手順、初回のモデル選択、音声起動の手間を実使用で見直す |
| 作業のそばにいる | 背後のクリックや入力を妨げず、表示・音・負荷が気にならない | 直接ドラッグの焦点問題、メモリ、様々な窓との組み合わせ、長時間使用 |
| 呼んで話す | 呼びかけへの反応、短い返答、声と口の動きの間が自然で、中止できる | 実AI→実音声→口形は1回成功。聞きやすさ・返答の長さ・待ち時間を実使用で評価する |
| 作業へ戻る | 会話を閉じると静かな常駐へ戻り、履歴や古い音声が勝手に復活しない | 実際の作業の流れで繰り返し使った確認 |
| 困ったら止める | 非表示・再表示・画面端への復帰・終了が確実で、失敗時の戻り方が分かる | 実スリープ・ロック、別PC、利用中の障害と復帰の確認 |

## 現在までの改善

2026-09-13、モデル選択中の非表示・休止を、遅い選択結果が取り消してしまう問題を再現して修正した。中断・保存待ち・再選択・終了の10項目と、既存の休止9項目が成功。追加の公式サンプルでも元画質／省メモリ表示・座り姿・左右の向き・描画復旧を短時間確認した。座った手の位置の自然さは調整が必要で、専用の外見を採用したものではない。[確認方法と素材の出典](model-compatibility.md)を参照する。

修正前の`937316a`を長めに動かし、27分の計測と会話20回、本体・検査の正常終了、残存0まで完了した。GPUは全802点が有効。静止3区間のCPU平均は約0.017〜0.019%、Working Set平均は約482〜603 MiBで、非表示は別に記録した。数時間の普段使いを保証する結果ではない。修正版は144単体・Build・audit 0件と上の受け入れ検査で確認した。

GPU採取は検査専用のWindows補助で復旧した。2026-09-13の各30秒の確認では、動く表示でGPU平均7.611%、静止・静止追従で0%を取得。別の約167秒・会話20回の短縮検査では4区間すべての計測、正常終了と残存0が成功した。途中でプロセスが増えた別実行の無効区間や、以前の欠測は成功へ読み替えない。

任意の[省メモリ表示](texture-quality.md)は元の画質へ戻せ、モデル自体を書き換えない。現在のモデルの短時間比較では保持画像のRGBA換算が88.25→52.25 MiBに減ったが、アプリ全体のメモリ削減量には起動間の差があり、一定の効果を保証する測定ではない。

会話は送信後の入力復帰、設定だけを閉じるEsc、応答不能通知での会話・音声の破棄まで整えた。実AI→VOICEVOX→実再生→口形→初期化は1回成功したが、声の聞きやすさや自然な間はまだ評価していない。外部AIは明示送信、声は毎回オフからの選択を維持する。

CDP（自動操作用の接続）なしの終了重複20回は成功した。一方、特殊なCDP focus設定でのネイティブ異常終了は旧版でも再現し、根因と実操作への影響は未確定。直接ドラッグの焦点問題、実スリープ・ロック、数時間の利用、別PCも残る。過去の失敗と修正後の測定条件は[検証記録](evaluation.md)に保持する。

## 進める順番

1. 27分の計測と別モデルの表示確認を踏まえ、座り姿の手の位置、実際の配置・入力・休止復帰、数時間の負荷を確かめる。開閉が重なる特殊な検査条件での終了異常も切り分ける。モデルファイル自体は書き換えない。
2. 利用者が自分の作業で使い、「邪魔だった」「待ちすぎた」「操作に迷った」ところを具体的に直す。会話・音声の有効化と外部送信の境界は維持する。
3. 呼ぶ→短い会話→閉じる、という流れの待ち時間・声・視線・動きを整える。新機能より、この流れの不自然さを優先する。
4. 新しい環境での準備、数時間の利用、休止と復帰、終了を確認し、対象条件を明示した最初の利用版にする。

専用の外見と声の最終的な印象は、しずくの体験に関わる判断として利用者と決める。現在の検証モデルを、制作済みのしずく専用モデルとは扱わない。市販DLCや未確認の素材は使わず、素材・音声・ソースの権利は別々に確認する。

## 完了の判定

テスト件数や機能数だけで完成としない。既存の安全性・停止・復帰の検査に加え、利用者が普段の作業で試した結果、同じ条件で比較した負荷、見た目と聞こえ方を判断材料にする。未検証の環境や制限は残す。ソースがPublicであることと、日常利用を勧められる完成度は別の状態として記録する。
