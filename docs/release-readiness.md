2026-09-10に [yutoo77/shizuku-desktop](https://github.com/yutoo77/shizuku-desktop) をPublicで公開した。対象はWindows x64・主画面1枚・手動起動の**ソースコードの技術試作**。インストーラーや安定版の完成を意味しない。

## 公開時に確定したこと

利用者から、この新アプリのPublic化、MIT採用、コミット作者メールの匿名化について明示的な許可を受けた。既存の別アプリに対する許可は流用していない。

- 新規ソースは[MIT License](../LICENSE)。モデル・音声は同梱せず、権利を一緒に付与しない。[第三者通知](../THIRD_PARTY_NOTICES.md)を保持する。
- 過去18コミットの作者・コミッターメールをGitHubのnoreplyへ置換した。各コミットのファイル内容、メッセージ、日時、作者名は同じ。番号の[対応表](history.md)を残した。
- 旧GitHubリポジトリはPrivateのバックアップとして別名で保持し、公開URLには別の新規リポジトリを作った。履歴を書き換えた旧リポジトリを直接Publicにはしていない。
- 新しいリポジトリへは匿名化済みのmainだけを送信した。ローカルの旧履歴・バックアップbundle・実行記録は公開対象外。

GitHubでは、force pushだけで古いコミットへのアクセスが必ず消えるわけではない。[公式説明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)を踏まえ、旧データをPrivateに保持したまま公開用リポジトリを分けた。この操作は、既存の別アプリや過去に共有された情報まで消去・匿名化したことを意味しない。

## 確認したこと

公開準備commit `b000fa2`のmainから到達できる19コミット、230個の履歴内blob（Gitに保存されたファイル内容）、当時の72追跡ファイルを検査した。全コミットの作者・コミッターメールが指定のnoreplyと一致し、旧メール、代表的な秘密情報パターン、モデル・録音・ローカル設定などの禁止パス、バイナリーの検出は0件だった。未知の秘密情報まで否定する検査ではない。

GitHubから新規cloneし、匿名化前の18コミットのオブジェクトが含まれないことを確認した。公開後は認証なしのHTTPで新リポジトリが200、旧18コミットのURLがすべて404、旧Privateバックアップが404になることを確認。認証付きの取得でも旧リポジトリがPrivateのままであること、新リポジトリが別IDの独立したPublicリポジトリであることを確認した。

公開準備のローカル検査は、型チェック・65単体テスト・Windows Buildが成功し、`npm audit`の既知の脆弱性は0件。アプリ本体のコードは変更せず、実画面・実入力の検査はこの公開作業では再実行していない。[以前のWindows検証と限界](evaluation.md)を参照する。

## GitHubの保護設定

公開後に、このリポジトリだけで以下を有効化し、APIで状態を再取得して確認した。

- Secret scanning：対応する形式の秘密情報を検出する。
- Push protection：対応する秘密情報がpushに含まれる場合に警告・保護する。
- Dependabot alerts：依存関係の既知の脆弱性を通知する。
- Private vulnerability reporting：脆弱性を非公開で報告できる。[SECURITY.md](../SECURITY.md)に入口と検証範囲を記載した。

これらは未知の秘密情報や脆弱性がないことの保証ではない。自動依存更新PR・自動マージ・有料の高度なスキャンは設定していない。独立した侵入テストも未実施。
