# 常駐して会話を繰り返す検査

しずくを置いたまま、呼んで短く話し、会話を閉じて作業へ戻る。その繰り返しで、会話窓や返答待ちが残らないか、静止描画が再び止まるか、負荷がどう変わるかを調べる。

## 実行する

Windowsの主画面1枚で、ローカルVRMを選択済みの開発環境を使う。起動・モデル選択・終了の手順は[README](../README.md)に記載している。通常のアプリを終了してから、プロジェクトのターミナルで実行する。

```powershell
npm run check
npm run test:daily-use
```

通常は約15分。途中の状況をターミナルに表示し、記録をGit対象外の`work/daily-use-*/run.json`へ残す。中断する場合はCtrl+C。中断時も途中の記録と、検査が起動したプロセスの終了を確認する。普段の設定とは別の設定を使い、選択済みVRMは読み取りと同一性の確認だけに使う。

| 順序 | 条件 | 期間・回数 |
| --- | --- | ---: |
| 1 | 元の画質・静止・会話なし | 5分 |
| 2 | 実際の設定から省メモリ表示へ切り替え、静止 | 5分 |
| 3 | 呼ぶ・入力・閉じる／中止／隠す | 20回 |
| 4 | 省メモリ表示・静止・会話なし | 2分 |
| 5 | 非表示 | 1分 |
| 6 | 終了 | 残存プロセスと設定・モデルの同一性を確認 |

各静止区間の前に反応が終わるのを待ち、さらに8秒を除外する。20回の会話は8回の定型返答、4回ずつの返答待ち中の閉じる・中止・非表示。保留する返答は検査用で、取消後に遅れて届いた結果が混ざらないことも確認する。毎回の新しい会話で履歴なし・音声オフ・定型返答を確かめ、会話のためにモデル画像が読み直されないことを数える。短時間に開閉を繰り返す検査で、人が会話する速さや自然さを評価するものではない。

`SHIZUKU_DAILY_DRY_RUN_SECONDS=30`を指定すると、4つの静止区間を各30秒にした短縮検査になる。記録に`dry-run`と残り、通常の15分前後の結果とは分ける。GPU計測を使えない環境では`SHIZUKU_DAILY_GPU=0`で明示的に外せる。取得できなかったGPU値を0とは記録しない。

長めの検査には`npm run test:daily-use -- --long`を使う。静止区間を元の画質10分・省メモリ表示10分・会話後5分・非表示2分とし、合計27分の測定と準備・会話・終了を行う。記録のmodeは`long`。短縮用の環境変数との併用や未知の引数は起動前に拒否する。数時間・終日の検査ではない。

## 結果の読み方

同じアプリを起動し続けた途中で画質を切り替えるため、別起動同士の公平な画質比較ではない。画質ごとの効果を比較した[前回の記録](texture-quality.md)とは分けて読む。会話中に専用プロセスが増減する時間も、静止中の平均へ混ぜない。

CPUは各プロセスが使った時間の差分をPCの論理CPU数で割り、補助プロセスは独自の時刻と分けて計算する。Working SetはRAM上のページ量で、プロセス合計には共有分の重複があり得る。Private Bytesは専用の割当量で、RAM上の量とは異なる。強制的なメモリ回収や、根拠のない増加量の合否基準は使わない。

安定区間の途中でプロセスが入れ替わったり、取得時刻に大きな隙間ができたりすると、その区間のCPU・メモリ集計を無効として理由と生データを残す。モデル表示・非表示・追加描画0・会話の廃棄などの機能検査は別に判定する。`functionalStatus`とCPU・メモリ区間の`measurementStatus`を両方確認し、機能検査の成功を計測全体の成功と読み替えない。GPUの有効数と欠測理由は、各区間の`gpu`を別に確認する。

GPUは静止区間ごとに、その区間のアプリと補助のPIDへ限定したWindowsカウンターを取得する。最も忙しいGPU処理系の利用率で、GPUメモリの測定ではない。区間途中で対象プロセスが変わった場合は有効な値と扱わず、欠測・対象時間も記録する。

終了確認は、記録したPIDと開始時刻、補助では実行名と親PIDを照合する。同じ番号が別プロセスへ再利用された場合は分けて記録し、照合できない場合は失敗とする。確認のために別プロセスを終了させることはない。本体の正常終了に加え、検査コマンド自身が終了してPowerShellへ戻ることも確認する。記録がpassedでも検査コマンドが残る場合は、検査全体の自力終了成功とは扱わない。

この検査は実Electron・ローカルモデルの描画とアプリ内部の操作である。外部AI・VOICEVOX・マイク・他アプリの内容・実マウス／キー・OSのスリープやロックは使わない。通信の確認はアプリ内の拒否と観測で、パケット全体の監査ではない。モデルの外見・声の自然さ、別PC、数時間から終日の安定性は別の検証が必要。[検証記録](evaluation.md)に実際に行った結果を残す。
