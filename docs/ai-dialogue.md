# AI会話を使う

呼びかけで開く会話窓から、OpenAIの`gpt-5.6-luna`へ短い文章を送れます。利用者自身のAPIキーを使う任意の機能です。音声オフの定型返答はキーなし・通信なしで使えます。任意のローカル読み上げは[音声の手順](voice-dialogue.md)を参照してください。

新しく開いた会話窓は毎回「お試し・AI未接続」で始まります。起動や「呼ぶ」、接続先を選ぶ操作だけではAIへ送信しません。

## 起動から終了まで

Windows、Node.js 24以上、PowerShell 7を使います。先に[通常の起動手順](../README.md#起動する)で`npm ci`を実行し、利用条件を確認したVRMを選んで、しずくを一度終了してください。APIキーは利用者自身がOpenAIで用意したものを使います。この手順は有料契約の作成や利用上限の変更を行いません。

アプリのフォルダで、次を順番に実行します。最初のBuildに成功してから、キーを入力してください。

```powershell
npm run build
if ($LASTEXITCODE -ne 0) { throw 'ビルドに失敗しました。表示されたエラーを確認してください。' }

$env:OPENAI_API_KEY = Read-Host 'OpenAI APIキー（画面には表示しません）' -MaskInput
try {
    & .\node_modules\.bin\electron.cmd .
} finally {
    Remove-Item Env:\OPENAI_API_KEY -ErrorAction SilentlyContinue
}
```

キーをコマンドそのものへ貼り付けず、`Read-Host`の入力待ちで入力します。これによりキーをPowerShellのコマンド履歴へ含めず、入力画面には伏せ字を表示します。キーはこの起動用の環境変数へ一時的に渡し、アプリ終了後に削除します。`.env`ファイルの自動読込、キーの入力画面、設定ファイルへの保存はありません。既に起動しているしずくがある場合は、先に終了してください。

1. `Ctrl + Alt + Shift + C`かトレイの「呼ぶ」で会話窓を開きます。表示だけでは作業中の入力先を変えません。
2. 右上の「…」から、返答を「OpenAI（従量課金）」へ切り替えます。切り替えると、それまでの会話と入力途中の文章を消し、返答待ちも中止します。
3. 入力欄をクリックして文章を入れ、「OpenAIへ送る」かEnterで送ります。Shift+Enterは改行です。送信時だけ入力と直近の会話をOpenAIへ送ります。
4. 返答待ちは「中止」で止められます。×かEscで会話窓を閉じると、アプリ内の会話と下書きを消し、しずくの常駐は続きます。次に呼ぶと空の定型会話から始まります。
5. アプリ全体はトレイの「終了」か`Ctrl + Alt + Shift + Q`で終了します。月のアイコンが消え、PowerShellへ入力待ちが戻ることを確認してください。ショートカットが競合する場合はトレイを使います。

日本語の変換中のEnterを送信扱いにしない処理がありますが、実際のIMEによる変換操作は未検証です。通常の会話操作と検証範囲は[README](../README.md#小さな会話を試す)を参照してください。

## 送る内容と上限

送信先は`https://api.openai.com/v1/responses`に固定しています。キーを扱うmain処理から通信し、会話画面には外部通信やファイル・デスクトップ操作を許可しません。履歴は送信ごとに必要な範囲だけ組み立て、サーバー側の会話IDを継続利用しません。

| 項目 | 範囲 |
| --- | --- |
| 今回の入力 | 1回1000文字以内 |
| 送信する会話履歴 | 完了した直近6往復まで、合計6000文字以内。古い往復から外す |
| 毎回の固定情報 | しずくの話し方、短い返答、見えない画面や使えない操作を装わない方針 |
| モデル | `gpt-5.6-luna`、推論設定`none` |
| 出力上限 | 400トークン（文章を分けて数える単位）。表示する本文は4000文字以内 |
| 受信上限 | APIの返答全体で128KiB、待機30秒 |
| 再試行 | 自動再試行なし。失敗後は利用者が再送する |

入力と固定方針は、履歴6000文字とは別に送ります。表示履歴は直近40発言までで、送信履歴の範囲とは異なります。中止・失敗した発言は表示に残る場合がありますが、次のリクエストの履歴には含めません。文字数はUTF-16単位で数えるため、絵文字などは複数文字分になる場合があります。

これらは、短い会話の試作で送信量と待ち時間を抑えるための上限です。400トークンは400文字という意味ではありません。長い返答が上限へ達した場合は未完了として扱い、短くして再送する案内を出します。画面画像、ウィンドウのタイトルや内容、モデル本体、音声、他のファイルは送信しません。

## 料金

2026-09-10に確認した[OpenAIの公式モデルページ](https://developers.openai.com/api/docs/models/gpt-5.6-luna)では、`gpt-5.6-luna`は100万トークンあたり入力$0.20、出力$1.20です。キャッシュへの書込みは通常入力単価の1.25倍、キャッシュ済み入力は100万トークンあたり$0.02とされています。実際の利用料金や条件は変更されるため、利用前に公式ページと自分のAPI利用状況を確認してください。

表示中に待機しているだけではAIへ送信しません。送信のたびに入力・履歴・固定方針が送られ、回数や会話量に応じて料金が増えます。このアプリは金額の上限や残高を管理しません。既存の利用上限を勝手に変えることもありません。自動再試行や常時送信は行いません。

## キーと会話の保存

利用者自身のキーで動かす方式です。キーはmain側の接続処理だけが保持し、アプリが画面・Windows補助プロセスを作る前に`process.env`から削除します。renderer（表示画面）・IPC（処理間の橋渡し）・設定・ログへキーを返しません。端末や同じ利用者権限の別プロセスが侵害されてもキーを守れるという保証ではありません。

アプリ内の会話はRAMだけに置きます。閉じる・明示的な非表示・接続先の切替・休止・ロック・画面構成の変更・終了で破棄し、復帰後に送信や会話窓を再開しません。中止した古い返答が届いても表示しません。

OpenAIへは`store:false`を指定しますが、送信先で保存が一切行われないという意味ではありません。2026-09-10に確認した[公式のデータ管理説明](https://developers.openai.com/api/docs/guides/your-data)では、APIデータは明示的な提供がない限り学習に使用されない一方、標準の不正利用監視ログには最大30日間保持される場合があります。GPT-5.6のプロンプトキャッシュには最大24時間の保存条件もあります。アプリで会話を消しても、OpenAIへ送信済みの内容を削除する操作にはなりません。中止しても、既に送った処理や課金が必ず止まるとは限りません。

この段階では新しいサーバーやSDKを導入せず、Electronに含まれる通信機能を使います。将来、開発者の契約で一般利用者へ提供する場合は、認証と利用上限を持つサーバーを別途設計します。開発者の共有キーをアプリに埋め込んで配布しません。[安全の方針](../SECURITY.md)も参照してください。

## うまく返答しないとき

| 表示・状態 | 確認すること |
| --- | --- |
| OpenAIを選べない | 起動時のキーが未設定または無効な形式。アプリを終了し、上の手順で起動し直す |
| キーと利用権限の案内 | 自分のAPIキーと対象モデルの利用権限を確認する |
| 利用上限・混雑の案内 | OpenAI側の利用状況を確認し、少し待ってから自分で再送する |
| 接続失敗・待機時間切れ | ネットワークとOpenAI側の状況を確認する。定型会話は引き続き使える |
| 返答が未完了・読取り失敗 | 入力を短くして再送する。繰り返す場合は対象commitと機密情報を含まない再現手順を報告する |

APIの生のエラー本文やキーを画面へ出さず、上の固定案内に置き換えます。キーや私的な会話をIssueへ貼り付けないでください。

## 検査と確認した範囲

通常の型チェック・単体テスト・Buildと、AI切替のElectron検査は、実APIキーなしで実行できます。Electron検査の前には、通常起動でVRMを選択・保存してアプリを終了してください。

```powershell
npm run check
npm audit
npm run test:dialogue
npm run test:ai-dialogue
```

`test:ai-dialogue`は偽の返答を使い、明示的な接続先選択、中止・切替・破棄、履歴の範囲、失敗時の案内などを調べます。テスト起動では本番のAPIキーを接続に使わず、実APIへの通信・課金は発生しません。結果はGit対象外の`work/ai-dialogue-*/`に保存します。通常の単体テストでは固定送信先、送信body、受信量、異常応答、通信中止を検査します。

2026-09-10の実API確認は架空の会話2回だけです。両方HTTP 200で、応答まで3030ms・1750msでした。2回目は直前の発言を参照して返答しました。これは接続と短い履歴の確認であり、会話品質全般、長時間の常駐、さまざまな通信障害での実挙動を保証しません。生の確認記録は非公開の`work/ai-live-rDQp8u/result.json`です。Windowsの実入力による確認は、このAPI検査とは分けて[検証記録](evaluation.md)へ残します。
