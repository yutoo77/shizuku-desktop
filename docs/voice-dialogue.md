# 声で話す

しずくの返答を、このPCで起動したVOICEVOXで読み上げます。定型会話とOpenAI会話のどちらでも使えます。**新しく開いた会話窓では毎回オフ**で、マイク入力はありません。読み上げのために外部の音声APIやAPIキーは使いません。

音声：**VOICEVOX:冥鳴ひまり**

## 起動と操作

1. [VOICEVOX公式サイト](https://voicevox.hiroshiba.jp/)から入手したVOICEVOXを、利用者自身で起動してください。この試作は、標準VOICEVOXの冥鳴ひまり・ノーマル（スタイルID 14）を含み、`127.0.0.1:50021`で動くエンジンを前提にしています。別のホスト・ポート・話者の設定画面はありません。
2. このアプリのフォルダで`npm start`を実行し、モデルを選んでしずくを呼びます。初回の準備は[README](../README.md#起動する)を参照してください。OpenAIと話す場合だけ、別途[AI会話の起動手順](ai-dialogue.md)が必要です。
3. 会話窓の右上の「…」を開き、**「声で話す」**をオンにします。切り替えるだけでは通信・読み上げを行わず、過去の返答も読み直しません。
4. 入力欄に短い文章を入れて「送る」またはEnterを押します。次に届くしずくの返答を読み上げます。入力した文章そのものを読み上げる機能ではありません。
5. 止めるときは「中止」か「声で話す」をオフにします。会話を消す、返答の接続先を切り替える、窓を閉じる、しずくを隠す、休止・ロック、アプリ終了でも、準備中・再生中の声を停止して遅れた結果を破棄します。復帰後に読み直しません。

会話窓を閉じても、しずくの常駐は続きます。しずくを終了する操作はトレイの「終了」または`Ctrl + Alt + Shift + Q`です。**このアプリはVOICEVOXを自動起動・インストール・終了しません。** 不要になったVOICEVOXは、そのアプリ側で終了してください。VOICEVOXが未起動でも、文字の会話は使えます。

音声ソフト・音声ライブラリ・VRM・生成音声は、このリポジトリにもアプリにも同梱していません。ソフトウェアと音声の利用条件は[第三者通知](../THIRD_PARTY_NOTICES.md#音声その他の素材)を確認してください。

## 聞こえないとき

- VOICEVOXが起動し、標準のローカル接続先で冥鳴ひまりを利用できるか確認してください。エンジンの仕組みと起動後のAPIドキュメントについては[公式README](https://github.com/VOICEVOX/voicevox_engine#api-ドキュメント)を参照できます。このアプリは接続先の探索や準備完了の繰り返し確認を行いません。
- Windowsの出力先・音量と、この会話窓の「声で話す」を確認してください。音声出力を準備できない場合は、文字の返答に戻ります。VOICEVOXへの接続・合成に失敗した場合も、届いた文字の返答は残ります。
- 1000文字を超える返答は途中で切らず、読み上げを省略して案内します。音声準備には30秒の通信上限があり、無制限に待機・再試行しません。再度試すときは短い文章を自分で送ってください。

## データと停止の範囲

通信は権限を持つmain処理から、固定の`http://127.0.0.1:50021`へ行います。1つの返答につき`audio_query`と`synthesis`を各1回呼び、リダイレクトや自動再試行は行いません。`audio_query`ではしずくの返答をURLのクエリに含めます。会話履歴全体・マイク・モデル・他アプリの内容はVOICEVOXへ渡しませんが、返答があなたの発言を引用していれば、その引用部分も含まれます。

画面側のネットワーク禁止は維持し、取得・検証した音声バイトだけを会話窓へ渡します。Web Audio（ブラウザーの音声再生機能）でメモリ上の音声を再生し、メディアURLや音声ファイルを開きません。音声と口の動きに必要なデータは使用後に破棄し、しずくアプリは文章や音声を保存しません。別に起動したVOICEVOX側のログ・保存はその設定に依存し、要求URLに返答文を含むAPIのためログに残る可能性があります。OS側のログ・メモリ処理も、このアプリから制御するものではありません。

中止はアプリ側の待機・再生を止め、結果を使わなくする操作です。通常の`synthesis`では、通信を切ってもエンジン内の計算が続く場合があります。[公式エンジンの説明](https://github.com/VOICEVOX/voicevox_engine#キャンセル可能な音声合成)にある実験的なキャンセルAPIは使用していません。OpenAIを選んだ場合の送信内容・課金・保存条件は、[AI会話](ai-dialogue.md)のままです。

## 実装上の上限と口の動き

| 項目 | 上限・固定値 |
| --- | --- |
| 読み上げる返答 | 1〜1000 UTF-16文字。絵文字などは複数文字分になる場合あり |
| 音声合成用のJSON | 受信256KiBまで。必要な項目を検証して組み直す |
| 音声バイト | 受信8MiBまで |
| WAV形式 | PCM・モノラル・24,000Hz・16bitのみ |
| 長さ | 合成前の見積もり・受信音声とも90秒まで |
| 合成用データの数 | 休符を含め1000モーラまで。モーラは日本語の短い音の単位 |
| 通信時間 | 2回の通信と本文読み取りを合わせて30秒まで |
| 声の設定 | 話速0.96・音高−0.01・抑揚0.94・音量1。現在は固定 |

再生中は音声の再生位置と音量から、対応するVRMの「あ・い・う・え・お」の口形を動かします。タイミングはVOICEVOXの音素時間を音声全体の長さに合わせた近似で、音ごとの完全な一致を保証しません。疑問文末へ追加される音を合成時に無効にし、合成用データとのずれを抑えています。

対応する口形がないモデルでも、文字と音声は使えます。モデルを別のものに置き換えたり、口形を新しく作ったりはしません。静止表示中も、自分で有効にした発話中は口だけ更新します。マイクで音を拾う処理はありません。

## 検証

`npm run check`と`npm run test:voice-dialogue`で検査します。後者には事前のBuildとローカルVRM選択が必要です。通常の自動検査は偽の合成応答を使い、実VOICEVOXや外部AIへ接続しません。

実エンジン、Electron内部の操作、Windowsの実入力、音の聞こえ方は別々の検証として扱います。実施済みの範囲は[検証記録](evaluation.md)に記載します。負荷を測るときは、しずく自身のプロセスと、利用者が別に起動したVOICEVOXのプロセスを分けて記録する必要があります。音声追加前の常駐測定だけでは、合成を含む負荷や長時間の安定性は判断できません。
