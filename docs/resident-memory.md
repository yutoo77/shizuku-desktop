# 常駐メモリの内訳

2026-09-10、`ac4abc0`のWindows開発ビルドで、モデル表示と会話窓の負担を分けて測った。これは改善前の短時間の原因調査で、省メモリ化の達成値や長時間の安定値ではない。

## 条件と結果

Playwrightから実Electronを起動し、モデルなしの新しいプロセスと、選択済みVRMを使う新しいプロセスを測定した。通常設定とは別のテスト設定を使用。各状態で8秒待った後、2秒間隔で3回取得したうち、時系列で中央のサンプルを以下に記す。計測用の接続による影響も含む。

| 状態 | ElectronのWorking Set合計 | Windows補助のWorking Set | ElectronのPrivate Bytes合計 |
| --- | ---: | ---: | ---: |
| モデルなし・操作窓を閉じた状態 | 316.63 MiB | 23.74 MiB | 193.04 MiB |
| VRM表示・動きを休める・会話を閉じた状態 | 619.78 MiB | 23.98 MiB | 666.82 MiB |
| 同じVRM・動きを休める・会話を開いた状態 | 728.93 MiB | 25.44 MiB | 712.45 MiB |

Working SetはRAM上にあるページの量。プロセス間で共有するページを合計時に重複計上し得る。Private Bytesは各プロセス専用に割り当てられた量で、すべてがRAM上にあるとは限らない。GPUメモリ使用量の直接測定ではない。VOICEVOX・外部AIは起動・呼び出ししていない。

検証モデルは約18.5 MB、46,984三角形、20描画命令、15 geometry、34 GPU texture。表示は300×440、DPR1、MSAA4で、静止中の繰り返し描画は停止していた。Windows 11・16論理CPUの既存検証PCを使用し、他アプリを止めた専有環境ではない。実行は11:16:22〜11:17:17 UTCの約55秒。通常設定のバイト一致と記録したアプリ・補助プロセスの終了を確認した。

会話を開いた前後のElectron差分はWorking Set約109.15 MiB、Private Bytes約45.63 MiB。モデルなしでも補助を含め約340 MiBあり、画像だけを直せば100 MiB程度になるという見通しは立たない。

## 画像データから分かったこと

モデル内には27画像、同じ圧縮データをまとめると23種類があった。実際に読み込まれたImageBitmap（描画に使う展開済み画像）は26個で、そのうち2048×2048が3個。単純なRGBA8換算で約88.25 MiB、すべてに縮小画像列を持たせる計算なら約117.67 MiB相当になる。ただし、これらは画像サイズからの概算で、実際のドライバーの割り当て量ではない。

同じ画像データの重複をすべてまとめても、モデル内全画像のRGBA換算では約6 MiB分。Threeは同じsourceと描画設定のtextureを既に共有しており、同じ画像が見えるという理由だけでGPU textureを統合すると、色や描き方を変えてしまう。

仮に読み込み時の最大辺を1024にすると、今回の実デコード画像ではRGBA換算約36 MiB、縮小画像列込みでは約48 MiB分の減少が見込まれる。CPU側とGPU側の両方に独立したコピーがある場合の合計概算は約84 MiBだが、**実測した削減量ではない**。小さい表示でも髪や服の細部への影響は実画面比較が必要で、現時点では縮小処理・画質設定を追加していない。選択したモデルファイルも書き換えていない。

現モデルのImageBitmapは、GPU描画が一時的に失われた後に同じモデルを戻すために保持している。GPUへ渡した直後に閉じると復帰を壊すため、モデルの破棄時に閉じる所有者管理を維持する。parserやGLB全体が常に残る参照は今回の静的調査では見つからず、根拠なく内部cacheを消す変更もしていない。

## 次の確認

画像失敗時の一時URLの解放を修正し、異常入力からの正常表示、隠す、再読込、描画復旧を回帰検査した。結果は[検証記録](evaluation.md)を参照する。正常表示の基本メモリ量を下げる変更ではない。そのうえで必要なら、画像の解像度を下げた実験と通常表示を同じ条件で比較する。差が小さい場合は設定や処理を増やさない。会話を閉じると専用rendererを破棄する現在の設計も維持する。

読み直し後にはWorking Setが短時間で大きく変動した。今回の3サンプルだけでメモリ漏れの有無や定常使用量を判定しない。長めのCPU/GPU/メモリ確認は[負荷の確認手順](evaluation.md)と`npm run test:resident`を使い、実VOICEVOXの合成中ピークと数時間の普段使いは別に評価する。

ローカルの生データ・測定スクリプトはGit対象外の`work/resident-profile-tSOHQW/result.json`、`work/resident-profile-run.mjs`。モデルと会話窓の画像を目視し、全身と透明な余白、最小限の会話UIが残っていることを確認した。モデル画像は公開対象に含めない。最初の試行は検査側の未初期化変数参照で中断し、修正後の成功runだけを上表に使用した。両試行とも記録対象プロセスの終了と通常設定の維持を確認した。
