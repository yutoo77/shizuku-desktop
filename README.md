# shizuku-desktop（仮称）

Windowsのデスクトップに、月白しずくが静かに寄り添うことを目指す個人開発アプリです。背景のないキャラクターを置き、呼ぶと短く反応して会話窓を開きます。普段の作業を妨げず、すぐ隠せる・戻せる・終了できる体験を重視しています。

**Windows x64・主画面1枚・手動起動を対象とする技術試作です。** インストーラー付きの安定版ではありません。対話・謎解きを主目的とする別の試作とは独立したアプリです。

[設計・開発の説明と3分デモ](docs/portfolio.md) · [操作の詳細](docs/usage.md) · [実使用チェック](docs/user-check.md) · [Windows CIの設定](.github/workflows/windows-check.yml)

## できること

- **静かな常駐**：透明表示、クリック透過、立位・座位・大きさ・向きの変更、静止表示。
- **配置と復帰**：ポインターでの移動、位置の保存、明示的に選んだ窓への着座と追従、非表示・画面端への復帰。
- **呼んで話す**：小さな反応と会話窓。既定はオフラインの定型返答。利用者のAPIキーと明示送信によるOpenAI会話、別起動のVOICEVOXによる読み上げと口形は任意。

検証用の **AvatarSample_A** はしずく専用の外見ではありません。VRM・音声ソフト・音声モデルは同梱しません。

## 起動する

Windows x64、Node.js 24以上、利用条件を確認したローカルのVRMが必要です。取得したリポジトリのフォルダをPowerShellで開きます。

```powershell
npm ci
npm start
```

初回は依存関係とElectron実行本体の取得にインターネット接続が必要です。表示と定型会話は準備後にオフラインで使えます。Windows用補助のビルドにはOS側の.NET Frameworkコンパイラーを使います。見つからない場合は自動導入せず理由を表示します。[準備と詳細](docs/usage.md#起動する)

操作窓の **「VRMを選ぶ…」** からモデルを選びます。窓が見当たらないときは通知領域の月アイコン（「^」内の場合もあります）を右クリックします。画像・データを内蔵したVRMが対象で、上限は100 MiBです。モデルのパスと配置などはGit対象外の`local.config.json`へ保存します。

| まず使う操作 | 方法 |
| --- | --- |
| 呼ぶ | `Ctrl + Alt + Shift + C` |
| ポインターで移動・確定 | `Ctrl + Alt + Shift + M`で開始、もう一度で確定。Escで取消 |
| 選んだ窓に座る | 対象窓をクリックして`Ctrl + Alt + Shift + W` |
| 隠す・戻す | `Ctrl + Alt + Shift + S` |
| 画面端へ戻す | `Ctrl + Alt + Shift + R` |
| 終了 | `Ctrl + Alt + Shift + Q`、または月アイコンの「終了」 |

キーが他アプリと競合する場合は月アイコンから操作できます。操作窓の×では常駐は終了しません。AI・声を使う場合は、[AI会話](docs/ai-dialogue.md)・[音声](docs/voice-dialogue.md)の準備と料金・利用条件を確認してください。

## 設計で重視したこと

**入力を邪魔しない。** 通常表示とポインター移動はクリックを背後へ通します。直接ドラッグには別アプリの入力先が外れる問題が残るため試験扱いとし、Mキーでの配置を通常操作にしました。

**途中でやめても戻れる。** 移動と窓選択には期限と取消を設け、遅れて届いた読み込み・会話の結果で、隠した表示や古い音声が復活しないようにします。

**必要な権限と情報に絞る。** Electron・TypeScript・Three.js／VRMを使い、画面と権限を持つ処理、Windowsの窓位置を読むC#補助を分離します。画面側のネットワークとNode.js利用を禁止し、通信元と引数を検証します。APIキーはmain処理だけで扱います。常時マイク・画面取得・自動起動・他アプリの自律操作はありません。

Electronは既存の描画技術とWindowsの操作を接続しやすい一方、実行本体の容量とメモリ負荷が課題です。[構成図、代替案、具体的な判断](docs/portfolio.md)を公開しています。本人の要件・優先順位の判断と、AIによる実装・検証支援も同文書で分けています。

## 確認できている範囲

モデル不要の型チェック・単体テスト・Windowsビルドは`npm run check`、依存関係の既知の脆弱性確認は`npm audit`で再現できます。[CIの範囲](docs/ci.md)と、アプリを起動する受け入れ検査・人の実操作は区別しています。

以下は**2026-09-13の同一Windows PC・主画面・AvatarSample_Aによる過去の測定**です。現在の版や別環境の性能保証ではありません。

| 測定した版と条件 | 結果 |
| --- | --- |
| 動く表示・静止・静止追従・非表示を各5分 | 動く表示はCPU平均約1.043%、約24.45fps。Working Set平均は各区間約502〜513 MiB。CPU／メモリ604点・GPU596点有効、終了後の残存0 |
| 別Buildで静止表示・画質切替・会話20回・非表示を含む2時間 | CPU平均約0.032〜0.047%、Working Set平均約476〜519 MiB。GPU3,592点有効、正常終了・残存0 |

CPUはPC全体比、Working Setは共有メモリの重複を含み得るプロセス合計です。別起動のVOICEVOXは含みません。静止の2時間検査は、動く表示・実AI・音声・人の日常作業を2時間確かめた結果ではありません。取得不能の値や途中失敗も含め、[条件・Build・限界を検証記録](docs/evaluation.md)へ残しています。

直接ドラッグの焦点問題、実IME・実スリープ／ロック、新しいPCへの導入、動く表示の長時間使用、声と間の自然さは確認・改善が残ります。メモリの小ささはまだ強みではなく、複数モニター、専用の外見、配布用インストーラー・署名・自動更新も後続です。[完成基準](docs/product-quality.md)と[次の開発](docs/roadmap.md)を参照してください。
