# shizuku-desktop（仮称）

Windows のデスクトップに、背景のないキャラクターを表示する個人開発アプリの試作です。選んだ窓の上辺に座り、窓の移動・幅変更・重なり順についていきます。別の窓を手前に出すと、その窓の後ろに隠れます。ポインターでの固定配置、位置・姿勢・大きさ・向きの記憶、静止表示も使えます。「呼ぶ」には短い反応を返します。月白しずくが静かにそばにいる体験を目指し、表示・移動・非表示・復帰・終了を検証しています。

既存の [adaptive-vrm-dialogue-agent](https://github.com/yutoo77/adaptive-vrm-dialogue-agent) とは別アプリ・別フォルダです。呼ぶと小さな会話窓を開きます。既定は無料の定型返答で、利用者自身のAPIキーを設定し、会話窓でOpenAIを選んだ場合だけAIと短く話せます。任意で、このPCのVOICEVOXによる返答の読み上げと口の動きも使えます。謎解きは未接続です。検証用の外見は **AvatarSample_A** で、しずく専用に制作したモデルではありません。モデル本体は同梱しません。

## 設計で重視したこと

今の開発目標は、毎日の作業で気持ちよく使えることです。[普段使いの完成基準](docs/product-quality.md)に沿って、静かな常駐、会話の間、使い始めやすさ、確実な停止と復帰を磨いています。

- **入力を邪魔しないこと。** 通常表示とポインター移動はクリックを背後へ通します。入力の焦点を保てなかった直接ドラッグは試験扱いとし、Mキーで開始・確定する操作を用意しました。
- **途中でやめても戻れること。** 窓選択と移動には取消・期限を設け、画面外からの復帰と終了をトレイ・キーの両方に残しています。休止前の一時操作を復帰後に再実行しません。
- **必要な情報だけを読むこと。** Electronの画面、権限を持つ処理、Windows用補助を分離し、明示的に選んだ窓の位置などに読み取りを限定します。窓の文章・画像・入力内容は取得しません。

型チェック・単体テスト・Windowsビルドに加え、実入力・実API・負荷測定を別に記録しています。AI接続では架空の会話2回が成功し、直前の発言を参照した返答を確認しました。会話窓を含む読み上げ後の短時間測定では、アプリと補助プロセスの使用メモリ合計は約738MiBでした。別起動のVOICEVOXは含まず、共有メモリの重複を含み得る値で、省メモリはまだ強みではありません。合成中のピーク、実際のPCのスリープ復帰、数時間の安定性は未検証です。[検証記録](docs/evaluation.md)と[今後の開発](docs/roadmap.md)で、確認済みの範囲と残る課題を分けています。

## 起動する

Windows と Node.js 24 以上、利用条件を確認済みのローカル VRM が必要です。PowerShell でこのフォルダを開き、順に実行します。

```powershell
npm ci
npm start
```

初回はインターネット接続が必要です。依存関係の取得に加え、Electron 44 の初回起動時に実行本体をダウンロードします。初回起動には時間がかかることがあります。モデル表示と定型会話はオフラインで使えます。外部AIは[AI会話の起動手順](docs/ai-dialogue.md)でキーを設定したうえで、会話窓で接続先を選んだ場合だけ利用します。

通知領域（時計の近く。隠れている場合は「^」）の月のアイコンを右クリックし、**「VRMを選ぶ…」** からファイルを選びます。初回は操作用の小窓も開きます。選べるのは画像・データをファイル内に内蔵した `.vrm` で、上限は画面表記の 100 MB（実装上 100 MiB）です。外部画像・外部データを参照するモデルは拒否します。

選択したモデルのパス・位置・大きさは `local.config.json` に保存します。この設定、モデル、`work/` の実行データは Git の管理対象外です。モデルをこのリポジトリへコピーする必要はありません。以前の設定に大きさの項目がなければ「標準」で始まります。

操作窓の「モデルと操作」では、画像を「元の画質」から「メモリを抑える」へ切り替えられます。大きな画像を縮小するため細かい模様が変わる場合があり、いつでも元へ戻せます。初期設定は元の画質です。切り替えるとモデルを読み直し、読み上げをオフにして窓への追従を止めます。モデルファイルは変更しません。[画像設定の効果と制限](docs/texture-quality.md)を確認してください。

## 呼ぶ・動かす・隠す・終了する

普段はキャラクターも透明な余白も、**クリックを背後へ通します**。Mで始めるポインター移動でも、この状態を保ちます。

| 操作 | 方法 |
| --- | --- |
| 選んだ窓に座って追従 | 対象の窓をクリックして `Ctrl + Alt + Shift + W`。再度Wで解除。操作窓の「窓を選んで座る」も使用可能 |
| 指定した場所に座る | 座らせたい場所へポインターを置いて `Ctrl + Alt + Shift + E`。操作窓の「3秒後のポインター位置に座る」も使用可能 |
| 位置を覚える・戻す | 操作窓の「この位置を覚える」で1か所保存。「覚えた位置へ」または `Ctrl + Alt + Shift + B` で復帰 |
| 左右を向く | 操作窓の「向き」、トレイ、または `Ctrl + Alt + Shift + F` |
| 動きを休める・戻す | 操作窓のボタン、トレイ、または `Ctrl + Alt + Shift + Z` |
| しずくを呼ぶ | `Ctrl + Alt + Shift + C`、トレイの「呼ぶ」、または操作窓の同名ボタン |
| 立つ・座るを切り替える | `Ctrl + Alt + Shift + P`、トレイの「姿勢」、操作窓の「立つ」「座る」 |
| ポインターで移動する・確定する | `Ctrl + Alt + Shift + M`で開始し、ポインターを動かしてもう一度Mで確定。トレイ・操作窓の「ポインターで移動」も使用可能 |
| 移動を取り消す | `Esc`、操作窓の「移動を取り消す」、または30秒経過で元の位置へ戻る |
| 直接ドラッグを試す | 操作窓の「モデルと操作」を開き、「直接ドラッグ（試験中）」を選ぶ。入力先が外れる問題が残るため、普段の入口からは移動 |
| 矢印で位置を調整する | トレイの「位置を動かす…」を開き、矢印ボタンで 16 ピクセルずつ移動 |
| 大きさを変える | 操作窓の「大きさ」、またはトレイの「大きさ」から「小」「標準」「大」を選択 |
| 隠す・再表示する | トレイの「隠す」「表示する」、アイコンのダブルクリック、または `Ctrl + Alt + Shift + S` |
| 見失った位置を戻す | トレイの「画面端に戻す」、または `Ctrl + Alt + Shift + R` |
| アプリを終了する | トレイの「終了」、または `Ctrl + Alt + Shift + Q` |

「呼ぶ」はボタン・キーによる操作です。隠している場合は再表示し、約 2.1 秒の小さな頷きと、モデルが対応する場合は控えめな表情変化で応じます。対応表情は `happy`、なければ `relaxed` を使い、どちらもないモデルでは表情を変えません。呼ぶだけではAIへ送信せず、音声・録音も使いません。

### 小さな会話を試す

「呼ぶ」で、しずくのそばに会話窓が開きます。表示時は作業中の入力先を変えません。話すときに入力欄をクリックし、文字を入れて「送る」かEnterを押してください。Shift+Enterで改行できます。日本語の変換中のEnterでは送らない処理を入れていますが、IMEの実変換操作はまだ未検証です。

新しく開いた会話窓は毎回「お試し・AI未接続」から始まり、挨拶などに用意した短い文章で返します。音声がオフの定型会話では、ネットワーク通信・APIキー・追加のサーバーは不要です。AIと話す場合は[AI会話の起動手順](docs/ai-dialogue.md)に従い、右上の「…」で「OpenAI（従量課金）」を選びます。「OpenAIへ送る」またはEnterで送った文章と、完了した直近の会話だけを送信します。接続先の切替で、会話と入力途中の文章を消し、返答待ちも中止します。

返答待ちには「中止」が現れ、失敗しても自分で再送できます。自動再試行は行いません。返答が届くと、表示中のしずくにも短い反応を渡します。中止した返答が後から届いても反応を再生しません。送信済みのAI処理や課金が必ず止まるわけではありません。

声を使う場合は、このPCでVOICEVOXを自分で起動し、「…」の**「声で話す」**をオンにしてから文章を送ります。音声は**VOICEVOX:冥鳴ひまり**で、次の返答から読み上げます。新しい会話窓では毎回オフに戻り、過去の返答を自動で読み直しません。準備・再生中も「中止」で止められます。対応するモデルでは5母音の口形も動き、音声が失敗しても文字の返答は残ります。[音声の起動・終了手順と制限](docs/voice-dialogue.md)を確認してください。VOICEVOXの自動起動・インストールは行わず、アプリ終了時も利用者が起動したVOICEVOXは終了しません。

会話窓の×、右上の「会話を閉じる」、または変換中でないEscで閉じると、しずくの常駐は続きます。会話と入力途中の文章は保存せず、閉じると破棄します。「…」から会話を消すこともできます。入力は1回1000文字まで、履歴はあなたとしずくを合わせて直近40発言までです。主に通常の日本語を想定した上限で、絵文字などは複数文字分として数える場合があります。

「隠す」、休止・ロック、画面構成の変更、終了でも会話を破棄します。復帰・再表示では会話窓を自動で開かず、もう一度呼ぶと空の状態で始まります。会話窓を見失った場合も、もう一度「呼ぶ」で主画面の中へ戻します。選んだ窓の最小化などでしずくが一時的に隠れる場合は、開いている会話窓を維持します。

会話窓はモデル読み取りやデスクトップ操作の機能を持たない、専用の通信経路を使います。入力をHTMLとして実行せず、取り消した返答が後から届いても表示しません。アプリ内の会話はメモリ内だけに置きますが、OpenAIへ送信した内容には同社の保存条件が適用されます。送信内容・料金・保存条件は[AI会話](docs/ai-dialogue.md)にまとめています。

定型会話の検査は`npm run test:dialogue`、AI切替と中止の検査は`npm run test:ai-dialogue`、音声の開始・停止・破棄は`npm run test:voice-dialogue`で再現できます。先にBuildとローカルVRM選択が必要です。いずれも偽の返答・音声応答を使う検査で、実VOICEVOXや外部AIへ送信せず、課金も発生しません。

「座る」では膝を曲げ、手を膝の近くへ寄せ、体を少し斜めに向けます。通常は約0.7秒の動きで切り替え、途中で逆の姿勢を選んでも反応をためません。隠している間は描画せずに選択だけ変え、「動きを減らす」設定では1枚だけ描いて切り替えます。姿勢は再起動後も残ります。常駐中に姿勢が勝手に切り替わることはありません。

窓の縁へ座らせるには、その場所へポインターを置いて `Ctrl + Alt + Shift + E` を押します。腰を基準に姿勢と位置を合わせるため、透明ウィンドウの角を目測する必要がありません。ボタンを使う場合は「3秒後のポインター位置に座る」を押し、3秒以内に置きたい場所へポインターを動かします。同じボタン、隠す、別の位置操作などで予約を取り消せます。モデルから推定する目印なので、合わないときは矢印で微調整してください。画面の端では、全身が作業領域内に残る位置を優先します。

Eキーの配置は固定です。窓についていく場合は、下のWキー操作を使います。Eではポインター位置を操作時に1回だけ取得し、常時監視しません。長いスカートなど、別の服・体型での姿勢と着座位置は未検証です。

### 窓についていく

1. 窓を最大化せず、上にしずくの全身が入る余白を空けます。その窓をクリックし、`Ctrl + Alt + Shift + W`を押すと、上辺の中央に腰を合わせます。
2. 窓を移動・リサイズすると、しずくもついていきます。もう一度W、または操作窓・トレイの「窓の追従をやめる」で画面端へ戻ります。
3. ボタンを使う場合は操作窓の「窓を選んで座る」を押し、20秒以内に対象の窓をクリックします。選んだ時点で座ります。Esc、同じボタン、操作窓を閉じる、時間切れで取り消せます。選ばずに終えた場合は位置・表示状態を保ちます。トレイの「座る窓を選ぶ…」は操作窓を開きます。

選択待ちの間だけ、操作中の窓が対象にできるか約50ms間隔で確認します。自分の操作窓やデスクトップ・タスクバーは対象にしません。クリック以外の方法で別の窓を前面に切り替えた場合も、その窓を選びます。Escが競合して使えない場合は、ボタン・操作窓の×・時間切れで取り消してください。選択中に「呼ぶ」「動きを休める」、配置や表示の操作をした場合も取り消します。

最小化、非表示、窓の上に全身を出せる余白がない場合、主画面外の場合は隠れて待ちます。同じ窓を戻すと再表示します。最大化した窓には通常、上の余白がないため隠れます。窓を閉じたときは追従を解除して画面端へ戻り、新しく開いた窓へ勝手に結び直しません。再起動後も、窓を選び直す必要があります。

追従中は、しずくを選んだ窓のすぐ手前に並べます。別の窓を手前に出すとしずくも覆われ、座っている窓を戻すと一緒に戻ります。対象が「常に手前に表示」の窓なら、その設定にも合わせます。解除後は通常のデスクトップ表示へ戻ります。重なりを合わせられない場合は追従を解除し、画面端へ戻ります。

「隠す／表示」「画面端に戻す」、固定配置、サイズ・姿勢・向きの変更、直接移動などを選ぶと追従を解除します。待機中に表示したい場合もSかRで戻せます。「呼ぶ」と「動きを休める／戻す」は表示中の追従を保ちます。呼びかけで隠れている状態から表示する場合は、追従を解除して画面端に戻ります。画面構成の変化、描画停止、補助プログラムの異常でも追従を解除します。

窓の位置・サイズ・最小化などの状態は、アプリに含む小さなWindows用補助プログラムが読みます。選択中の1枚だけを約50ms間隔で確認し、変更時に位置を渡します。最前面の設定と、すぐ手前がしずく自身の窓かどうかも確認します。並びを変えるのはしずく自身の窓だけです。ウィンドウのタイトル・画面画像・文章・入力は読みません。選択を解除すると窓の確認を止め、アプリ終了時には補助プログラムも終了します。別の窓を動かしたり、入力したりする機能はありません。

Windows標準の.NET Frameworkの仕組みを利用し、このPCでは追加インストールなしでビルドできました。`npm run build`が`native/WindowTracker.cs`を`dist/window-tracker.exe`へコンパイルします。コンパイラーの場所は`Windows/Microsoft.NET/Framework64/v4.0.30319/csc.exe`です。別のPCで存在しない場合は自動導入せず、ビルドで理由を表示します。出力EXEは11,776バイトでGitに入れず、ソースを管理します。x64 Windowsでの試作であり、インストーラーやARM64対応は未検証です。

専用の通常窓を使い、実クリックで手前に重ねると隠れ、対象窓を戻すと再び現れることを確認しました。最前面設定の切替は専用窓のAPI検査です。仮想デスクトップ切替、全画面アプリ、管理者権限の窓、独自の重なり制御を持つアプリは未検証です。状態や利用条件の詳細は[検証記録](docs/evaluation.md)を参照してください。

「この位置を覚える」は位置・大きさ・姿勢・向きを1か所分保存します。「覚えた位置へ」で再表示してその組合せに戻ります。複数の保存枠はありません。新しく覚えると以前の位置を置き換えます。「画面端に戻す」はこの記憶を上書きせず、いつでも使えます。

「向き」はモデルの回転で左右を切り替えます。「動きを休める」は呼吸や瞬きと繰り返し描画を止め、静止した姿で残ります。この間の「呼ぶ」は短い表情変化だけで応じます。位置・サイズ・姿勢は静止中にも変更でき、非表示中は描画しません。向き・休止設定・覚えた位置は再起動後も残ります。OSの「動きを減らす」が有効な場合は、アプリで動きを戻しても静止表示を優先します。

静止表示中も、自分で「声で話す」を有効にした発話では、対応モデルの口だけを更新します。静かな姿に戻したいときは音声の「中止」または「声で話す」をオフにしてください。

反応中の連打は受け付けず、後の反応をためたり延長したりしません。隠す、移動を始める、モデルを読み直すと反応を取り消します。OS の「動きを減らす」が有効な場合は頷かず、対応する表情だけを一時的に静止表示して戻します。

移動の手順は次のとおりです。

1. モデルが表示されたら `Ctrl + Alt + Shift + M` を押します。ポーズが一時的に止まり、移動中だけ短い案内が表示されます。
2. ボタンを押さずにポインターを動かします。開始位置からの移動量に合わせてしずくが動き、画面の外へは出ません。姿勢・向き・サイズを保ちます。
3. もう一度 `Ctrl + Alt + Shift + M` で確定します。操作窓の「この位置に置く」でも確定できます。操作窓にポインターがある間は位置を止め、ボタンを押しやすくしています。

`Esc`または操作窓の「移動を取り消す」で元の位置に戻ります。開始から30秒で自動的に取り消します。Escを他アプリが使用していて登録できない場合も、操作窓と時間切れで取り消せます。移動中だけポインター座標を約33ms間隔で読み、確定・取消・非表示・別の配置操作・描画停止・終了でタイマーを止めます。画面画像や入力内容を読まず、他アプリの焦点を操作しません。確定前の位置は設定に保存しません。

このPCの専用入力窓で、実キーのMによる確定、Escによる取消、どちらの直後も入力欄に焦点が残ることと、その後の文字入力を確認しました。すべてのアプリや入力環境での保証ではありません。

試験中の直接ドラッグは、見えている体を左ボタンでつかみ、離すと終了します。ポインター移動とは別の操作です。直接ドラッグ後に元の入力欄から焦点が外れる問題は未解決なので、通常は上のM操作か矢印を使ってください。

大きさは次の3段階です。寸法は透明な余白を含む描画領域を表します。

| 選択 | 幅 × 高さ |
| --- | --- |
| 小 | 240 × 352 |
| 標準 | 300 × 440 |
| 大 | 360 × 528 |

大きさを変えるときは、描画領域の下辺中央を基準に位置を保ちます。画面からはみ出す場合は内側へ補正し、作業領域が小さすぎる場合は縦横比を保って縮小します。「画面端に戻す」や再起動でも選択した大きさを維持します。隠している間に大きさを変えても、勝手に再表示しません。

**ドラッグ後の入力の焦点は確認中です。** この PC の実マウス検証では、移動前に入力先だった別アプリが、移動後には入力先でなくなる結果が出ています。しずくの窓もAPI上は非フォーカスでしたが、別アプリへの入力を維持できたとはいえません。移動後に文字が入らない場合は、入力したい欄を一度クリックしてください。

描画が一時的に使えなくなると、トレイや操作窓に復旧待ちの状態を表示し、「呼ぶ」と移動を一時停止します。まず復旧を待ってください。戻らない場合は、トレイの「終了」または `Ctrl + Alt + Shift + Q` で終了し、`npm start` で起動し直します。プロセスの自動再起動は行いません。

位置操作の小窓を閉じても常駐は続きます。終了すると月のアイコンが消え、起動元の PowerShell に入力待ちが戻ります。ショートカットが他のアプリと競合して登録できない場合は、トレイから操作・終了してください。

### スリープ・画面ロックの前後

Windowsから休止や画面ロックの通知を受けると、しずくと操作窓を隠して描画を止めます。移動途中なら開始位置へ戻し、窓選択・着座の予約・呼びかけを取り消します。スリープとロックが重なった場合は、両方が終わってから戻ります。Windowsの電源設定や自動起動は変更しません。

戻るのは休止前の表示状態です。手動で隠していた場合は隠れたままにし、途中の操作を再開しません。窓への追従は解除し、表示していたしずくは画面端へ戻ります。再び追従させるには窓を選び直してください。操作窓を開いていた場合は焦点を取らずに再表示します。

窓を読む補助プロセスは維持しますが、休止中は選択窓の確認を止めます。休止による応答の途切れを故障と判定せず、復帰時から再び応答を待ちます。補助そのものが終了した場合は、従来どおりアプリの再起動が必要です。

この対応はアプリ内に休止通知を送る模擬検査9項目と、模擬復帰後のWindows実画面・入力先の維持・文字入力・終了で確認しています。**PCを実際にスリープ・ロックした検証はまだ行っていません。** 再現検査は`npm run test:rest`で行えます。このコマンドはPCをロックせず、通常の設定も変更しません。

位置操作の小窓のタイトルバーを動かすとキャラクターが追従する処理もありますが、このタイトルバーの実ドラッグは未検証です。しずく自身のドラッグとは別の確認項目です。表示・復帰時には主画面の作業領域内へ位置を補正します。

## 今の範囲と確かめ方

会話追加前のビルドを各状態60秒ずつ測り、このPCではCPU平均が通常約1.08%・静止約0.07%、補助を含む常駐メモリは約514〜528MiBだった。最初の測定はGPUプロセスの一時的な増減で無効になり、条件を変えず再測定した結果。短時間の値であり、会話窓を含む負荷や数時間の安定性、省メモリ化の成果は主張しない。詳しい条件と失敗記録は[検証記録](docs/evaluation.md)に残す。

対象は Windows、主画面 1 枚、手動起動です。検証 PC には画面が 2 枚接続されていますが、主画面内だけを検証しています。複数画面への移動・異なる拡大率への対応を保証するものではありません。

描画領域は上の3段階、描画の細かさを指定する DPR は 1、上限 30 fps です。影や床は描かず、非表示時と移動モード中は描画タイマーを止めます。OS の「動きを減らす」設定に対応する場合は静止表示になります。実測値・実画面の確認内容・未検証項目は [検証記録](docs/evaluation.md) にまとめます。

モデルを読み直すときは、使い終わった画像データ（ImageBitmap）も明示的に解放します。読み込みが重なった場合も、現在表示しているモデルの画像は保持します。描画の上限 30 fps は変更していません。

WebGL（GPUで描く仕組み）の一時的な停止には、モデルと画像を保持したまま復旧する処理を追加しました。停止中は描画・呼びかけ反応・直接移動を止め、復旧しても古い呼びかけを再生しません。自分のキャンバスを使う模擬検査10項目が成功し、非表示の維持、モデル再読込との組合せ、停止中の終了を確認しました。復旧後の画像も全身と服・髪の表示を確認しています。実際のスリープ復帰やGPUドライバー障害、復旧中の物理キーによる入力先維持は未検証です。

以前の Windows 実マウス操作では、しずく自身のドラッグで右へ 26・下へ 41 ピクセル移動し、移動モード中でも透明な余白を通して背後のボタンを押せました。今回のサイズ追加では、実マウスで操作窓の「小」を選び、下辺中央を保って縮小できたことを確認しました。「標準」「大」の手操作と、サイズ変更後の実ドラッグは未確認です。3サイズの寸法・描画範囲・入力領域、保存・再起動・復帰は Electron の検査で確認しています。

通常の表示・非表示での焦点維持と、ドラッグ後の焦点の問題は分けて記録しています。後者は今回も解消できていません。ウィンドウの重なり順も調整しましたが、全画面アプリや自動的に隠れるタスクバーとの組み合わせは未検証です。

「呼ぶ」は Electron の検査で、短い反応の終了・連打の抑制・隠した状態からの復帰・移動や再読み込みとの取り消し・動きを減らす設定での静的な表情変化を確認しました。実マウスや物理ショートカットを使った入力先の維持、反応が自然に感じられるかどうかは未検証です。

画像解放を修正した`f71bc0d`で、表示5分・非表示1分と、呼びかけ・表示切替・サイズ変更の15回反復を確認しました。このPCの表示中はCPU平均約1.05%（PC全体比）、メモリ平均約482MiBでした。非表示の描画とGPU使用は止まりましたが、CPUは計測経路を変えた補足検査で差が出たため、単一の定常負荷とは断定していません。以前の約494MiBとの差も修正効果には数えません。これらはWebGL復旧処理を追加する前の測定値です。数時間単位の常駐、バッテリー消費、スリープ復帰、幅広いGPUやVRMは今後の確認対象です。条件と限界は[検証記録](docs/evaluation.md)、次の順番は[開発の進め方](docs/roadmap.md)に残しています。

```powershell
npm run check
npm run smoke
npm audit
```

ポインター移動は`npm run test:pointer`、窓選択は`npm run test:picker`、窓への追従は`npm run test:follow`、重なり順は`npm run test:order`、補助の終了は`npm run test:native`で検査できます。アプリを終了してから、1つずつ実行してください。窓選択の検査では専用窓を使い、補助側の20秒の期限も実時間で待って確認します。APIによる選択結果の受渡しと、実クリックによる窓選択は分けて評価しています。

補助を含む負荷の再測定は、しずくを終了した状態で`npm run test:resident`を実行します。通常・静止・静止追従・非表示をそれぞれ2分測り、終了処理を含めて約10分かかります。確認用の窓が1枚表示されますが、この計測では入力先にならない設定を使います。自動の画面撮影やキー操作は行いません。生データとGPUカウンターは`work/resident-.../`へ保存します。CPUは計測による負荷も含む短い観測値で、1日常駐の保証ではありません。

`check` は型検査・単体テスト・ビルドを実行します。`smoke` は、通常起動で選択・保存した VRM のパスを使い、実際に Electron を起動して表示・移動・大きさ・呼びかけ反応・復帰・終了などを検査します。検査用の設定と実行データは `work/` 内の別フォルダへ分け、普段の `local.config.json` が変わっていないことも確認します。これらの成功だけでは、Windows の実マウス操作やフォーカス（キーボード入力の行き先）を確認したことにはなりません。

描画の復旧・画像の解放・短時間の常駐を調べる場合は、先に通常起動で VRM を選んでアプリを終了し、`npm run check` でビルドした後、必要な検査を一つずつ実行します。

```powershell
npm run test:context
npm run test:postures
npm run test:resources
npm run soak
```

`test:context` は、しずく自身のWebGL描画を一時停止・復旧させ、呼びかけ・移動・非表示・モデル再読込・終了との組合せを検査します。結果は `work/context-*/result.json`、復旧前後の画像も同じフォルダに保存します。実際のスリープやGPUドライバーの停止は行いません。

`test:resources` は選択済みの VRM を実際に読み直し、古い画像が解放され、表示中の画像は残ることを検査します。メモリ内で生成した壊れたテスト画像でも、一時URLが解放され、その後に正常なモデルへ戻れることを確かめます。選択したモデルは書き換えません。画像を使う VRM が対象です。結果は `work/resources-*/result.json` に保存します。

`soak` は約 7 分かかります。起動直後の 20 秒を除き、標準サイズで 5 分表示・1 分非表示の CPU とメモリを別々に計測し、その後に呼びかけ・表示切替・サイズ変更を 15 回繰り返します。検証アプリは最後に終了します。進捗と結果の保存先は `work/soak-active.json`、詳しい結果はその `reportPath` が指す `work/soak-*/run.json` で確認できます。終了時の `status` が `passed` であることを確かめてください。数時間の安定性を保証する検査ではありません。

いずれも検査用の設定を `work/` に分離し、通常のモデル選択・位置・大きさを変更しません。記録には端末情報やローカルのパス、モデルの確認画像が含まれるため、個人データとして Git の管理対象外に置きます。CPU・メモリの数値やプログラムからの操作確認を、実マウス操作の検証へ読み替えないでください。GPU は `soak` と別に採取します。採取条件と評価範囲は [検証記録](docs/evaluation.md) を参照してください。

手元では、別アプリへ入力しながら表示・非表示・復帰を行い、普段は透明部分とキャラクター部分の両方で背後をクリックできることを確かめてください。「呼ぶ」操作で短く反応して普段の表示へ戻ること、反応後も入力を続けられることを確認します。大きさを切り替えて全身が見えること、隠して変更しても再表示しないこと、再起動しても選択が残ることも確認します。続けて移動モードを始め、透明な余白へのクリック、しずくのドラッグ、ボタンを離した後のクリック透過と入力先を確認します。最後に終了し、月のアイコンと関連プロセスが消えることを確認します。

## 技術の選択

Electron を試作に採用しました。既存の TypeScript・Three.js・VRM の知識を使い、Windows の透明ウィンドウと通知領域を小さな構成で扱えるためです。単なるブラウザー画面では、デスクトップ上のクリック透過や常駐の操作を同じようには検証できません。

移動モードでは、止めたポーズの描画結果から透明でない画素を取り出し、Windows がマウス入力を受ける領域をその形に限定します。WebGL の画素を使うため、読み取るのはしずく自身の描画だけです。CSS のウィンドウ移動領域は使わず、押した位置からのマウス移動量で位置を更新します。

代替の [Tauri](https://v2.tauri.app/concept/) は OS 側の WebView を使う構成で、配布容量を抑える候補です。一方、Rust 側の実装や Windows の表示・操作の再検証が増えます。今回は既存コードとの接続のしやすさを優先し、実測負荷が日常利用に適するかを先に判断します。

Electron 自体に利用料はありませんが、Chromium・Node.js を含むため実行本体の容量と複数プロセスのメモリ負荷があります。ダウンロード量、展開後容量、CPU・GPU・メモリの実測は [検証記録](docs/evaluation.md) を参照してください。配布用インストーラー、署名、更新の運用は未実装で、[OpenAIのAPI料金](docs/ai-dialogue.md#料金)も別です。学習・説明上の価値は、ウィンドウの振る舞い、安全なプロセス間通信、常駐負荷を測定して判断する部分にあります。

## 安全とデータ

描画側では Node.js を使えないようにし、sandbox（OS によるアクセス制限）と context isolation（画面と権限のある橋渡し処理の分離）を有効にしています。必要な操作だけを公開し、通信元と引数を検証します。画面の外部通信・外部ページへの移動・追加ウィンドウ・権限要求も制限します。基準は [Electron の公式セキュリティガイド](https://www.electronjs.org/docs/latest/tutorial/security) です。依存関係の更新管理は継続して必要です。

OpenAIとの通信は、権限を持つmain処理に限定します。利用者自身のAPIキーを起動時の環境変数から受け取り、画面・設定ファイル・Gitへ渡しません。起動・呼びかけ・接続先の切替だけでは送信せず、会話窓でOpenAIを選んで文章を送った場合だけ、固定の公式APIへ接続します。追加サーバーや新しいnpm依存は導入していません。
